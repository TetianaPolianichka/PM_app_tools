# Data to collect (per competitor)

## Identification
- Name, developer (as in the store)
- Official site
- Links to the App Store (`apps.apple.com/<country_code>/...`) and Google Play (with the `gl=<country_code>` parameter)

## Store metrics (iOS and Android separately)
- Rating: as shown in the store, 1 decimal
- Number of ratings or reviews: as shown in the store, noting what exactly is counted (ratings or reviews)
- Last update date: YYYY-MM-DD
- Android: download range (e.g. "10M+")
- iOS: category position, only if shown on the page (e.g. "#5 in Education")
- Age rating

## Monetization
- Model: free / freemium / paid / subscription / hybrid
- Purchase or subscription prices: from the App Store In-App Purchases section or the site, in CURRENCY
- Free trial: yes / no / n/a, duration
- In-app ads: yes / no / n/a (Google Play marks "Contains ads")

## Product
- 3–5 key features from the store description, briefly paraphrased
- Main product format or approach
- Target audience, as the app itself describes it (if stated)
- Interface languages (if stated)

## Mechanics relevant to APP_NAME
- For each mechanic in KEY_MECHANICS: yes / no / n/a, from the source.
- If KEY_MECHANICS is empty, identify 4–6 mechanics that recur most often in the category and mark them as an analysis result.

## ASO signals
- Name and subtitle (iOS) or short description (Android), verbatim
- Main messages in the description and screenshots (paraphrased)
